# 自动化回归测试

项目使用 Playwright 对真实前端、真实 API 和独立 MySQL 测试数据库执行核心流程回归。

## 安全边界

- 测试数据库名称必须以 `_e2e` 结尾，否则执行器立即拒绝运行。
- 默认以独立 Compose 项目名 `hgt-e2e` 启动 `hgt-mysql-e2e` 容器，使用 3307 端口和内存临时盘；结束后只删除该测试项目的容器及数据，禁止清理其他 Compose 项目。
- 测试进程显式使用本地 Cookie、JWT、邮件、AI 和对象存储配置，不读取或改变生产认证配置。
- 不允许把 `E2E_DB_NAME` 指向开发库或生产库。

## 首批覆盖流程

1. 用户注册、退出和重新登录。
2. 发布海龟汤、编辑并保存。
3. 点赞、收藏、评价及刷新后的状态持久化。
4. 卡包每日免费抽取用尽后，商城列表和详情状态一致。
5. 创建玩汤房间、发送消息及重新进入后的消息恢复。

## 本地运行

前置条件：Docker 可用，并且本机安装 Microsoft Edge。默认流程不会连接现有开发 MySQL。

```bash
npm run test:e2e
```

需要观察浏览器操作时：

```bash
npm run test:e2e:headed
```

保留失败后的测试数据库用于排查：

```bash
E2E_KEEP_DATABASE=1 npm run test:e2e
```

只有 CI 或明确准备好的隔离数据库才应设置 `E2E_EXTERNAL_DB=1`。此模式要求通过 `E2E_DB_HOST`、`E2E_DB_PORT`、`E2E_DB_USER`、`E2E_DB_PASSWORD` 和以 `_e2e` 结尾的 `E2E_DB_NAME` 提供专用数据库，执行器会在运行前后重建并删除该库。

CI 使用 Playwright 自带 Chromium 时，先执行 `npm run test:e2e:install`，并设置 `PLAYWRIGHT_USE_BUNDLED_CHROMIUM=1`。

失败时的截图和 trace 位于 `test-results/`，HTML 报告位于 `playwright-report/`。
