# 阿里云短信验证码调用手册

## 1. 能力边界

服务端通过 `apps/server/src/sms.ts` 提供阿里云短信验证码发送能力：

- 仅支持中国大陆手机号；
- 仅支持 6 位数字验证码；
- 固定使用环境变量配置的短信签名和验证码模板；
- 不提供公网 HTTP 接口；
- 不负责验证码生成、存储、频控、校验或消费，这些逻辑由调用模块负责。

调用模块禁止把用户输入直接作为模板 Code、签名或模板参数名传入阿里云。

## 2. 阿里云前置配置

在阿里云短信控制台完成以下准备：

1. 创建短信专用 RAM 用户，只授予发送短信所需权限，不复用 OSS AccessKey。
2. 准备审核通过的国内短信签名。
3. 准备审核通过的验证码模板，模板变量名必须是 `code`，例如：

   ```text
   您的验证码为：${code}，请勿泄露给他人。
   ```

4. 从控制台取得模板 Code，例如 `SMS_123456789`。

## 3. 环境变量

在运行环境中配置：

```dotenv
ALIYUN_SMS_ENDPOINT=dysmsapi.aliyuncs.com
ALIYUN_SMS_ACCESS_KEY_ID=replace-with-sms-ram-access-key-id
ALIYUN_SMS_ACCESS_KEY_SECRET=replace-with-sms-ram-access-key-secret
ALIYUN_SMS_SIGN_NAME=审核通过的短信签名
ALIYUN_SMS_VERIFICATION_TEMPLATE_CODE=SMS_123456789
```

禁止把真实凭据写入 `.env.example`、源码、日志或版本库。

短信配置是可选能力：缺少配置不会阻止服务启动，但调用发送接口会抛出 `not_configured` 错误。

## 4. 标准调用

业务模块使用以下接口：

```ts
import { sendVerificationSms } from "./sms.js";

const receipt = await sendVerificationSms({
  phoneNumber: "+8613800138000",
  code: "012345",
  outId: "bind-phone:challenge-id"
});

console.log(receipt);
// {
//   provider: "aliyun",
//   requestId: "阿里云请求 ID",
//   bizId: "阿里云发送回执 ID"
// }
```

参数说明：

| 参数 | 必填 | 说明 |
|---|---:|---|
| `phoneNumber` | 是 | 支持 `13800138000`、`8613800138000`、`+8613800138000`、`008613800138000`，发送前统一规范化为 11 位大陆手机号 |
| `code` | 是 | 6 位数字字符串；需要保留前导零，因此不能使用 number |
| `outId` | 否 | 业务侧追踪标识，不得包含手机号、验证码、密钥等敏感信息 |

成功返回只表示阿里云已受理请求，不代表运营商已经送达。需要核实最终送达状态时，使用返回的 `bizId` 查询阿里云发送记录。

## 5. 错误处理

```ts
import {
  sendVerificationSms,
  SmsDeliveryError
} from "./sms.js";

try {
  await sendVerificationSms({ phoneNumber, code, outId: challengeId });
} catch (error) {
  if (!(error instanceof SmsDeliveryError)) throw error;

  switch (error.reason) {
    case "not_configured":
      // 服务端配置缺失，告警并返回服务不可用。
      break;
    case "invalid_phone":
    case "invalid_code":
      // 调用参数错误，不应重试。
      break;
    case "provider_rejected":
      // 阿里云业务拒绝；记录 providerCode/requestId 后按错误码处理。
      break;
    case "transport_error":
      // 网络或超时错误可能是暂时性故障，但不能直接自动重试。
      break;
  }
}
```

错误字段：

| 字段 | 说明 |
|---|---|
| `reason` | 稳定的内部错误类型 |
| `retryable` | 是否属于暂时性传输故障；不代表允许立即重发短信 |
| `providerCode` | 可选的阿里云或网络错误码 |
| `requestId` | 可选的阿里云请求 ID，用于排查 |

`SendSms` 不具备幂等能力。发生 `transport_error` 或超时时，即使 `retryable=true`，也应先利用业务挑战记录和阿里云发送记录确认结果，再决定是否重新发送，禁止在请求链路中自动重试。

## 6. 业务模块接入要求

调用发送接口前，业务模块必须自行完成：

1. 使用安全随机数生成 6 位验证码，并以字符串保存。
2. 只持久化验证码摘要，不保存明文验证码。
3. 设置有效期、单号码和单 IP 发送频控、每日上限及最大校验次数。
4. 先建立待发送挑战记录，再调用短信接口；发送失败时将挑战标记为失败或删除。
5. 校验成功后一次性消费挑战，避免验证码重放。
6. 对外响应不得返回验证码、完整手机号、阿里云原始错误或任何凭据。

当前接口内部已执行以下保护：

- SDK 自动重试关闭，最多发起一次请求；
- 连接超时 3 秒，读取超时 5 秒；
- 手机号日志脱敏为 `138****8000`；
- 日志不包含验证码、模板参数或 AccessKey；
- 仅阿里云响应 `Code === "OK"` 时返回成功。

## 7. 配置检查与测试

代码中可在不发送短信的情况下检查配置：

```ts
import {
  isSmsDeliveryConfigured,
  smsDeliveryConfigurationError
} from "./sms.js";

if (!isSmsDeliveryConfigured()) {
  console.error(smsDeliveryConfigurationError());
}
```

运行短信单元测试：

```bash
npm run test:sms -w apps/server
```

运行服务端类型检查和构建：

```bash
npm run check -w apps/server
npm run build -w apps/server
```

单元测试使用注入的模拟客户端，不会调用阿里云，也不会产生短信费用。真实发送测试必须使用受控测试手机号、已审核模板和明确的测试验证码。
