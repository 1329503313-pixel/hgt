# 登录体系改版：本地实现与迁移核验

## 已实现

- 新注册：仅支持中国大陆手机号，短信验证码和密码必填；保留昵称和邀请码。手机号唯一。新用户沿用用户 ID 关联业务数据，内部随机账号不开放登录或展示。
- 登录：手机号及密码、原始账号及密码两个入口。普通历史用户验证原始密码后可进入平台；每次重新打开网页或 APP 都会弹出绑定手机号提示，可选择“稍后”，直至完成绑定。个人中心设置页也提供“绑定”入口。绑定手机号、验证短信并设置新密码后，关闭原始账号入口，旧登录态与重置凭据失效。旧版 10 分钟绑定凭据接口暂保留兼容。
- 超级管理员：不要求手机号，可在手机号输入框使用原始账号及原始密码登录。
- 找回：已绑定手机号短信验证码，或已验证的绑定邮箱验证码；保留旧邮件链接兼容入口。成功重置后旧登录态与升级凭据失效。无已绑定联系方式且忘记原始密码的历史用户，先人工核实，再由后台重置，之后按原始账号登录并绑定手机号。
- 后台：用户列表显示原始账号及手机号，可按两者搜索；新用户的原始账号显示“无”。后台改密覆盖当前密码，必须填写原因，并记录操作人、目标用户和原因。
- 账号设置显示脱敏手机号；换绑须人工核实。

## 数据迁移策略

这是增量迁移：仅为原用户表增加三个带默认值或可空的字段，并新建验证码、升级令牌和审计表。现有用户的 ID、原始账号、密码哈希及业务关联行均不重写。历史账号默认允许原始账号验证，只有完成手机号绑定的事务才关闭原始入口并替换密码。新账号使用独立标识。手机号身份的唯一键防止同一手机号绑定到两个用户。

迁移审计脚本 scripts/auth-migration-audit.mjs 使用只读事务对用户关键字段和已有身份记录做摘要快照与比对。发布前使用只读数据库账号执行 snapshot；部署完成后停止相关账号写入或在维护窗口执行 verify。若摘要不一致，必须调查具体变更后才能确认迁移完整。该脚本不导出原始密码哈希、手机号或邮箱。

生产数据尚未迁移、未执行生产快照或部署；因此此处只证明本地迁移路径和测试夹具，不声称已证明线上用户数据完整。

## 本地核验

- 本地回环 MySQL 的独立前缀夹具已通过：旧账号和超级管理员行不变、新用户标识有效、同手机号重复绑定被拒绝；测试不读取或改写原用户行。
- 本地原始用户基线为 4 个用户、1 条身份记录、1 个超级管理员，快照前后摘要相同；这只是当前本机数据库，不是生产库。
