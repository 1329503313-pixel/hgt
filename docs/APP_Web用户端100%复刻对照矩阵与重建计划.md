# HGT Android APP：Web 手机端用户侧 100% 复刻对照矩阵与重建计划

> 文档性质：非业务规范、非新的交互规则来源；这是 Web → Android APP 的范围清单、差异台账、重建顺序和验收门禁。
>
> 业务与跨页面规则仍以 `docs/前端交互与展示统一规范.md` 为唯一规范来源；发生冲突时以当前 Web 手机端源码和该统一规范共同校验，不能由本文件创造新规则。
>
> 基线日期：2026-08-10。源码基线为当前本地工作树（Git HEAD `d50f27b`，并包含用户尚未提交的 Web/玩汤/统一规范改动）。实施前必须重新冻结一次基线，避免开发期间 Web 继续变化而无人同步。

## 1. 已确认的产品边界

1. 只复刻 Web 用户端，不包含 `/admin` 管理后台及任何后台管理能力。
2. APP 只以 Web 手机端为唯一视觉、信息层级、图标语义、交互和流程基准；不复刻 PC 导航、PC 三栏工作区、PC 迷你房间和 PC 页脚布局。
3. 首期只实现 Android；iOS 不进入本轮范围，也不能用 Android 结果宣称 iOS 完成。
4. 底部导航严格复刻 Web 手机端：`首页 / 玩汤 / 创作 / 圈子 / 我的`。消息从移动顶栏 `Bell` 进入，不占用底部 Tab。
5. 现有 `apps/app` 只作为接口和兼容性探索样本，不作为新 UI 的结构底座；禁止继续逐页修补形成第二套混合架构。
6. 不部署、不发布、不改生产环境。Android 真机调试必须默认连接本地或隔离环境，不能默认连接正式 API。
7. 用户端中由角色控制的功能仍需复刻，例如 VIP/管理员身份在用户端可见的 AI 玩汤开关；仅后台页面本身排除。
8. Web 手机端可直接到达的协议、隐私、社区公约、AI 服务说明等内容属于用户侧内容，纳入 APP；浏览器 SEO、站点页脚和桌面悬停行为不纳入。

## 2. “100% 复刻”的可验收定义

100% 不能仅凭“复用了 React/Tailwind 代码”或截图大致相似来宣称完成。共享源码可以消除双端漂移，但仍必须验证以下六类等价：

| 维度 | 等价标准 |
|---|---|
| 功能 | Web 手机端可到达的每个入口、操作、权限分支和结果在 Android 均存在；排除项只能来自本文件第 1 节。 |
| 视觉 | 同一视口下的信息层级、顺序、颜色、字体层级、圆角、间距、阴影、图片裁切、图标及状态视觉一致。 |
| 交互 | 点击、长按、横滑、滚动、展开、关闭、确认、返回、键盘切换、按压反馈和禁用反馈一致。 |
| 逻辑 | 请求参数、权限判断、幂等、防重复提交、分页、缓存、未读、已读、撤回、回复、定位、计数和服务端真源一致。 |
| 状态 | 首次加载、骨架、空、错误、重试、弱网、断网恢复、前后台、过期会话、资源失败、无权限和数据变化状态一致。 |
| 体验 | 触控目标、安全区、系统返回、软键盘、动态字体、无障碍名称、减少动态效果和低端 Android 性能达到同等可用性。 |

验收时不接受以下说法：

- “功能已经有了，只是入口不同。”
- “原生 APP 就应该换一种样式。”
- “图标意思差不多。”
- “轮询也能最终看到，所以等同实时。”
- “正常数据能用，空状态和错误状态以后再做。”
- “模拟器通过，真机应该也没问题。”

## 3. 真源优先级与冻结方式

### 3.1 真源优先级

1. 当前可运行的 Web 手机端用户行为及源码。
2. `docs/前端交互与展示统一规范.md` 中已确认的跨页面规则。
3. 服务端当前 API、WebSocket/SSE 语义、权限与事务规则。
4. Web 共享组件：`BottomNav`、`PageTopBar`、`SoupCard`、`LevelBadge`、`BadgeVisuals`、聊天/送礼/分享组件等。
5. `mobile_ui_design_guide.md` 只补充未被当前 Web 明确覆盖的基础值。
6. 现有 `app规范`、旧 App 页面和 `docs/APP视觉与图标对齐执行说明.md` 仅作历史线索，不可覆盖以上真源。

### 3.2 每轮冻结产物

实施任何模块前，必须冻结：

- Web 路由和入口清单。
- 对应页面在 320、360、375、390、430px 宽度下的手机截图。
- 游客、普通用户、VIP、内容作者、已关注/未关注、主持人/玩家/旁观者等相关角色截图。
- loading、empty、error、disabled、pending、success、无权限、资源失败状态。
- 该模块实际请求、事件类型、导航来源和返回目标。
- 使用的 Lucide 图标名、token、图片裁切方式和动画规则。

Web 在实施期间发生变化时，先更新矩阵和冻结样本，再改 APP，禁止两端凭记忆追赶。

## 4. 当前 App 状态标记

| 标记 | 含义 |
|---|---|
| `M` | 缺失：没有入口、页面或完整业务链路。 |
| `P` | 部分：有页面或接口，但功能、状态、视觉、逻辑任一关键部分不等价。 |
| `R` | 重建：现有实现结构不适合作为新版本底座，应重新实现。 |
| `K` | 候选复用：可以复用，但必须先通过契约、视觉或真机验证。 |
| `X` | 明确排除：不属于 Android 用户端范围。 |

当前诊断中的“部分存在”不计作交付进度。只有通过对应验收门禁后才能改为完成。

## 9. 新 Android 客户端架构

### 9.1 重建策略

第一性原理结论：既然唯一目标是 100% 复刻当前 Web 手机端，最可靠的方案不是把 React/Tailwind 逐页翻译成第二套 UI，而是让 Web 与 Android 使用同一份用户端组件、路由、状态、图标和业务逻辑，再由 Capacitor 提供 Android 原生容器。

- 新 Android 工程固定为 `apps/app-android`，采用 Capacitor 8；`apps/app` 仅作旧版历史参考。
- 用户端真源抽为 `apps/web/src/UserApp.tsx`，Web 和 Android 共同使用。底部导航仍是同一个 `BottomNav.tsx`，不存在第二份临摹实现。
- Android 使用独立入口 `main.android.tsx` 和独立 Vite 模式；构建期排除 `/admin`、SEO 与桌面页脚。
- APK 只加载随包构建的 `dist-android` 本地资源，禁止以线上网页 URL 作为生产入口。
- Android 专属代码只处理系统栏/安全区、系统返回、文件、分享、相机/相册、下载/安装更新等平台边界；业务规则继续留在共享用户端。
- Release 本地来源固定为 `https://app.caqis.com`，API 固定为 `https://hgt.caqis.com`，保持同站点 httpOnly Cookie 模型；Debug 使用 `http://app.localhost` 与 `http://api.localhost:4000`。
- 全部用户端真机门禁通过后，再提出替换旧 App 的单独方案；未经确认不删除旧 App、不上传 APK、不发布。

### 9.2 强制依赖方向

```text
Android native shell / platform adapters
  → Android entry
  → shared UserApp / layouts / components / pages
  → shared context / API / realtime / cache
  → server contracts / constants
```

Android 层禁止：

- 复制一份用户页面再单独维护。
- 用原生近似组件替换已有 Web 视觉和流程，造成双真源。
- 自行保存或读取 JWT；认证继续使用服务端 httpOnly Cookie。
- 手写第二份等级、徽章、头像、图标、底部导航和未读规则。
- 在请求成功前伪造余额、抽卡、送礼、房间或权限结果。
- 使用 `server.url` 加载线上站点作为 Release 入口。

### 9.3 已落地目录

```text
apps/web/src/
├── UserApp.tsx          # Web/Android 共用的全部用户端路由与全局浮层
├── AndroidApp.tsx       # Android 入口壳
├── main.android.tsx     # Android provider/Router 入口
├── runtime.ts           # API/WebSocket/站点 URL 的目标环境适配
└── pages/components/... # 与 Web 手机端完全相同的用户端实现

apps/app-android/
├── capacitor.config.ts  # 本地资源、来源、安全区和 Debug/Release profile
├── android/             # 可版本控制的 Android Studio/Gradle 工程
└── release/
    ├── version.json     # versionName/versionCode 单一真源
    └── signing-certificate.sha256

scripts/android/
├── setup-jdk.ps1
├── setup-android-sdk.ps1
├── create-signing-key.ps1
├── build-android.ps1
└── verify-android-artifact.ps1
```
